How Dijkstra's Algorithm Works

Dynamic Weighted Shortest Path Mechanics

1

Initialize Distances

Set tentative distance to Origin = 0. All other nodes = ∞. Insert Origin into the Min-Priority Queue (Binary Min-Heap).

2

Greedy Selection

Extract unvisited node $u$ with the minimum tentative cost from the Priority Queue in $O(\log V)$ time.

3

Dynamic Edge Relaxation

For each outgoing road edge $(u, v)$, compute dynamic weight:

$\text{Edge Cost} = \text{Distance (km)} \times \text{Road Multiplier} + \text{Traffic Delay}$
  • Normal Road = 1.0
  • Express Shortcut = 0.5
  • Yellow Traffic Light = +1.5
  • Red Traffic Light = +4.0
  • Blocked Road = Infinity

If $\text{dist}[u] + \text{cost}(u,v) < \text{dist}[v]$, update $\text{dist}[v]$ and record predecessor.

4

Backtrack Optimal Path

Upon reaching the Destination, backtrack predecessors to assemble the sequence of road coordinates for Leaflet polyline rendering and smooth vehicle animation.

ℹ️ About CityNav Simulator

This application is an educational, production-quality city navigation simulator demonstrating Dijkstra's Algorithm on a realistic road network in Hyderabad, India.

Architectural Separation:

  • Leaflet 1.9.4: Used strictly for geographic map presentation, OpenStreetMap tiles, SVG markers, and polyline visualization.
  • Custom Pure JavaScript Engine: Dijkstra's Algorithm, Binary Min-Heap Priority Queue, dynamic traffic weight calculation, and road snapping are implemented manually without any external routing API (no Google, Mapbox, or OSRM).
  • Single Source of Truth: Road geometry coordinates drive both the displayed route polyline and the 60fps vehicle animation.

Dynamic Real-Time Recalculation:

Every 3 seconds, traffic lights cycle between Yellow (1.5) and Red (4.0). If a signal delay makes an alternative boulevard cheaper, Dijkstra reroutes dynamically and smoothly transfers the moving vehicle.
