How Dijkstra's Algorithm Works

Shortest Path & Travel-Time Optimization Mechanics

1. Algorithmic Overview

Dijkstra's Algorithm finds the minimum-weight path from an origin node to all other nodes in a weighted directed/undirected graph with non-negative edge weights. This simulator implements a Binary Min-Heap Priority Queue running in O((V + E) log V) time.

2. Realistic Edge-Cost Model (Travel-Time vs Distance)

In real city driving, the geographically shortest path is frequently congested or impeded by red signals. The simulator demonstrates two distinct cost functions:

Normal Route Cost: $\text{Distance} = \sum \text{edge.distance (km)}$
Dijkstra Fastest Cost: $\text{Time (min)} = \left(\frac{\text{Distance}}{\text{Speed (km/h)}}\times 60\times\text{Multiplier}\right) + \text{Signal Delay}$
  • Normal Road: 45 km/h base speed (Multiplier: 1.0)
  • Express Shortcut: 65 km/h high-speed bypass (Multiplier: 0.85)
  • Green Signal: +0s delay (clean flow)
  • Yellow Signal: +20s delay (+0.33 min)
  • Red Signal: +75s delay (+1.25 min)
  • Blocked Road: Weight = $\infty$ (impassable)

3. Step-by-Step Traversal

  1. Initialize: Tentative cost to Origin = 0; all other nodes = $\infty$. Insert Origin into Min-Heap.
  2. Greedy Extraction: Extract unvisited node $u$ with minimum tentative cost.
  3. Edge Relaxation: For each neighbor $v$ via road $(u, v)$: $$\text{If } \text{cost}[u] + \text{weight}(u, v) < \text{cost}[v] \implies \text{Update } \text{cost}[v] \text{ and set Predecessor}[v] = u$$
  4. Backtracking: Upon reaching the Destination, backtrack predecessors to assemble the complete sequence of road geometry coordinates.
